# docs/benchmarks — orientation

What lives here, and what lives next to the code.

## Two kinds of measurement, two homes

spiritwriter-core measures itself in two distinct ways. Both live under
the project's `benchmarks/` tree, but the docs split them by audience:

| Question you're asking | Where to look |
|---|---|
| "How fast does the engine run?" — ops/sec, latency, scale | Code: [`benchmarks/bench_*.py`](../../benchmarks/) · Docs: [`benchmarks/README.md`](../../benchmarks/README.md) |
| "How *correct* is the engine?" — precision, recall, false-merge rate, per-tier calibration | Code: [`benchmarks/eval/`](../../benchmarks/eval/) · Docs: **this directory** |

The perf benches answer load questions. The eval suites (under
`benchmarks/eval/`) answer correctness questions and produce citable
artifacts for peer reviewers, marketing copy, and design audits.

## What's in this directory

| File | Purpose |
|---|---|
| [`ess-accuracy-spec.md`](ess-accuracy-spec.md) | The **design doc** for the ESS-accuracy harness. What invariants it asserts, what it doesn't claim, where each artifact lives, history of the design. Read this if you want to understand the *framework*. |
| [`runs-log.md`](runs-log.md) | The **campaign report**. Per-corpus measurements with pinned `report.md` / `results.json` / `pairs.tsv` artifacts; cross-corpus invariants; falsification-battery results; recommended marketing copy. Read this if you want the *numbers*. |

## Reading order for newcomers

**If you're trying to validate a marketing claim or pick a number to cite:**
go straight to [`runs-log.md`](runs-log.md) → "What this means for
marketing claims" section. The pinned per-corpus reports there are
reproducible — each `report.md` was generated by the same runner code
that's still in `benchmarks/eval/ess_accuracy/`.

**If you're trying to understand how the harness works:**
read [`ess-accuracy-spec.md`](ess-accuracy-spec.md) for the framework,
then look at [`benchmarks/eval/ess_accuracy/`](../../benchmarks/eval/ess_accuracy/)
for the implementation.

**If you want to add a new corpus and measure your own domain:**
the bring-your-own-corpus process is documented at
[`benchmarks/eval/README.md`](../../benchmarks/eval/README.md), with a
worked example at
[`benchmarks/eval/ess_accuracy/data/people/`](../../benchmarks/eval/ess_accuracy/data/people/).

**If you want to add a new eval suite (not just a new corpus to the
existing one):**
[`ess-accuracy-spec.md`](ess-accuracy-spec.md) is the template — adapt
its pass/fail-invariant + per-family-attribution shape to your domain.

## Why this is split from the code-level README

The `benchmarks/eval/README.md` lives next to the runnable code; it
covers *how to invoke* the harness and *how to add a corpus*. The docs
here (spec + runs-log) cover *why the harness exists*, *what claims it
defends*, and *what we actually measured*. Code-adjacent docs tell you
*what to type*; these tell you *what to cite*.
